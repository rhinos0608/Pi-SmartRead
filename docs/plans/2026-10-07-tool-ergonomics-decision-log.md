# Tool ergonomics decision log

Program: make SmartRead's specialist tools (`inspect`, `LSP`, and the long tail of `grep`/`read` options) actually get used when they help, and prove it with audited benchmarks. Decisions are made between the orchestrator and an oracle advisor; each entry records evidence and status. Earlier program history lives in `2026-10-06-decision-log.md` (D1–D60); this log starts at E1.

Comparator reviews and the borrow/import log live in `2026-10-07-comparator-reviews.md`.

## Context carried in

- Observational, unaudited: across ~300–355 recent child sessions, `read` ~85% session uptake, `grep` ~53%, `find` ~26%, `inspect` ~1%, `LSP` 0. Confounds: task mix (benchmark/dataset work), and guidance delivery (below).
- Guidance delivery gaps found on `main@3aa32fd`:
  1. Tool guide injected only on the first `before_agent_start` per session via a forced `systemPrompt` (one-turn lifetime); later prompts get no guide and no repo map.
  2. Forced `systemPrompt` text is not recorded in transcripts, so runs cannot be audited for guide exposure.
  3. Standalone MCP server sends no `instructions`.
  4. `skills/` is not shipped: explicit `pi` manifest lists only `extensions`, and `files` omits `skills/`.

## Decisions

### E1 — Guidance delivery design (approved by user, 2026-10-07)
- A: per-tool `promptSnippet`/`promptGuidelines` generated from `src/runtime/tool-guidance.ts`; remove forced-`systemPrompt` guide injection.

- C: MCP server `instructions` from the same guide text.
- D: SmartRead-owned skill sync into `~/.pi/agent/skills` with `.smartread-managed` marker, on `session_start` (automatic, one-time notice — user chose option A) plus `scripts/install-skills.mjs`; opt-out `PI_SMARTREAD_SKILL_SYNC=0`; `skills/**` added to `files`; no `pi.skills` (duplicate-name warnings).
- Status: implementing.

### E4 — Skill-sync hardening before merge (orchestrator, from reviewer BLOCK, 2026-10-07)
Confirmed findings: (1) a copied/forged `.smartread-managed` marker in a differently named dir could authorize removal — realistic case is a user copying a managed skill to customise it; fix: marker records the skill name and removal/update require `marker.skill === dirname` and the shipped package name; (2) symlink swap after the one-time check — re-`lstat` immediately before each mutating op; (3) failed move-into-place after moving the old dir aside must restore it; (4) aside/staging paths must be fresh unique names (never delete a pre-existing path we did not create); (5) sync errors must surface in the session notice. Threat model: anything with write access to `~/.pi/agent/skills` can already alter skills; the goal is never deleting user data by accident, not resisting a local attacker.

### E5 — Residual root-swap race in skill sync (orchestrator + reviewer, 2026-10-07)
Re-review confirmed items 1–5 fixed, and found a remaining race: swapping the skills root for a symlink between the root `lstat` and `rm` can redirect removal (deterministic repro needed an injected swap between syscalls). Node has no `openat`/`unlinkat`-bound rm, so this cannot be fully closed. Decision: mitigate by resolving the root with `realpath` once at sync start and doing every operation on that canonical path (a later swap of `~/.pi/agent/skills` then has no effect); swapping an ancestor of the real path requires control of the user's home directory and is out of scope under E4's threat model. Residual risk documented in code.

### E6 — Tool Ergonomics Bench (TEB) program (orchestrator + oracle `335b14b6`, 2026-10-07)
Adopted from the oracle plan with these binding points:
- D71's runner (`/tmp/ab-chunk.mjs`) is a pilot, not a baseline: only `grep,read` were allowed, ambient skills/context were not disabled, tool use was self-reported, no usage/cost captured, 19/40 sessions timed out. TEB gets a durable runner under `scripts/eval/teb/` with JSON-event capture.
- Corpus: new pinned JS/TS repos disjoint from D46 and the external-grep manifests. Splits: ~24 pilot, ~64 dev, ~120 sealed holdout; stratified by repo and family; negative controls included.
- Labels record an *opportunity* (specialist could improve evidence or cost), never a mandatory tool. Holdout: two independent source-first, tool-output-blind labelers on **all** tasks + adjudication before sealing.
- Grading is script-checkable structured answers (locations, sets, file lists); gold for semantic families comes from a pinned language server driven directly (not through SmartRead's tool) and is cross-checked; inspect output is never its own gold. Graders get unit tests for correct/near-miss/ambiguous/stale/malformed answers.
- Arms: baseline (post-E1 tools, guidance on), one arm per isolated intervention (natural choice), and an instructed-specialist arm as a diagnostic upper bound only. Isolation: `pi -ne -e <worktree>/src/index.ts --mode json --no-session --no-skills --no-context-files --no-prompt-templates`, explicit model + tool list, `PI_SMARTREAD_SKILL_SYNC=0`; skill delivery evaluated separately.
- Primary metric: paired script-graded task success. Secondary: opportunity recall, specialist-call precision, invalid-call/recovery rate, calls/tokens/time to first correct evidence, negative-control overuse. Paired task bootstrap CIs with repo-clustered sensitivity.
- Promotion gate (calibrated on pilot, frozen before dev results, never relaxed after opening): holdout success +5pp with positive paired 95% CI, opportunity recall +15pp, specialist precision ≥ 80%, loss veto ≤ 3pp on negative controls and ≤ 5% lost prior successes. Uptake rising without score is not success. One sealed-holdout opening for one predeclared champion.
- Model: `claude-bridge/claude-sonnet-5` primary (comparable with D71; user default); 24-task transfer slice on `openai-codex/gpt-6-luna`. Pilot is metered from `message_end` usage; large paid runs need a measured cost estimate shown to the owner first.
- Intervention order: (1) description input examples, (2) stateless `{path,symbol}` anchors with explicit ambiguity/staleness errors, (3) inspect named views, (4) bounded nextActions / doom-loop toolInput, (5) optional LSP task presets, (6) opaque handles only if anchors fail. Each additive; strict LSP validation and proposal-only semantics preserved. Stop on invalid-call growth, negative-control over-routing, answer losses, or gains that vanish under natural choice.
- Retrieval regression guards on dev only: D46 dev56, internal 44, external grep dev64 title/body, pinned LSP fidelity; comparators ripgrep/Probe/Codanna (grep), pi-lsp/mcp-language-server (LSP), plus pinned Serena where operations are genuinely equivalent; same source, commit, budgets and grader; setup time separated; comparator mechanism, pin, hypothesis and any borrow logged *before* implementation.

### E10 — Orchestrator resolutions of the TEB protocol's remaining open items (oracle recheck `6786fb57`, 2026-10-08)
To stop the revise/recheck loop on contract details, these are decided:
1. A frozen family→`answerType`→gold table lives in the protocol. `useSite` is optional and absent for non-semantic families; semantic tasks carry `anchorKind: "use" | "definition"`; callers tasks anchor at the definition site (probe: `prepareCallHierarchy` is empty at use sites).
2. `package-exports` grades files only (`file-set` of package entry files per `package.json` exports); the symbol half is dropped.
3. Structural opportunities name real calls (`inspect {mode:"file", path, analysis:{...}}`, `inspect {mode:"directory", path, analysis:{routes:true}}`, etc.). Where `inspect` renders a bounded top-N list, task gold must not exceed that bound, otherwise the task is not an inspect opportunity.
4. Event extractors are written against actual result shapes (strict LSP `details.envelope.{status,result}`; grep/read/find/inspect rendered text). "First correct evidence" = first successful tool result whose rendered text contains a gold location/file, excluding strings that already appear in that call's arguments. `unavailable` envelopes are counted separately from errors. "Recovery" is renamed `post-error success rate`.
5. Every ordinary timeout is a failure in the primary denominator, including double timeouts. Infrastructure exclusions are predeclared and narrow: provider/auth failure before the first assistant token, extension load failure, runner crash — each logged with artifacts.
6. Tool allowlist for every arm: `read,bash,grep,find,inspect,LSP` (bash included because it is the real-world substitute for specialist tools; no `edit`/`write` because tasks are read-only). The instructed arm uses a frozen per-family one-line substitution naming the tool only (no operation or arguments) and never applies to negative controls. The session table is a maximum, not an exact count.
Implementation proceeds in parallel against these resolutions; the protocol text is amended to match and rechecked.

### E20 — Product-bet lane: rigor must not filter for small interventions (owner feedback + orchestrator, 2026-10-08)
Owner concern, accepted: the program so far optimises for proving small isolated deltas (BM25 `b`, stemming, filename prefix, coverage) because they decompose cleanly; the larger product gains are likely in changes that do not decompose (task recognition, richer specialist affordances, multi-step evidence gathering). Isolation-first ordering is itself a bias. Decision:
1. **Two lanes.** Lane K (knobs, E15/E18) continues unchanged. Lane P (product bets) evaluates *bundles* first: build the full affordance bundle behind one switch, compare bundle vs baseline on TEB with the same paired statistics and loss vetoes; only if the bundle wins, ablate to attribute and simplify. A bundle that loses is dropped as a whole, not salvaged knob by knob.
